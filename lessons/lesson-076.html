1#

题型: 判断题 难度: 中等

题干: 当 Temperature 设置为 0 时，同样的 Prompt 调用多次，大模型的输出在文本层面完全一致。(延展题)

正确答案

错误

解析

这是一个非常容易踩的坑。理论上 T=0 等价于贪心采样，每一步都选最高概率词，输出应当确定。但在工程实现上，主流 API（OpenAI、DeepSeek 等）在 T=0 时仍可能出现微小差异，原因来自：并行计算浮点误差、负载均衡时调度到不同 GPU、模型多副本部署、以及后端对 logits 的轻微扰动优化。因此要真正"完全可复现"，需要同时固定 seed、关闭流式输出、指定模型版本，而不仅仅是把Temperature 设为 0。

2#

题型: 简答题 难度: 困难

题干: 假设你是一个 SaaS 产品的开发者，同一个大模型 API 需要同时服务于三类用户请求：①客服咨询（必须稳定）、②营销文案（需要一定创意）、③头脑风暴（希望天马行空）。请从 Temperature的角度设计一个分层策略，并说明为什么不能用一个统一的 Temperature 值处理全部三类请求。 (思维题)

参考答案

● 分层策略：客服咨询统一设 T=0 到 0.2（锁定确定性回答，避免模型乱编政策细节）；营销文案设T=0.7 到 0.9（保留一定创意但不失控）；头脑风暴设 T=1.2 到 1.5（允许跳脱联想，即使偶尔跑题也能激发灵感） ● 为什么不能统一：如果全部用 T=0，头脑风暴会重复同一套陈词滥调，产品价值丧失；如果全部用 T=1.2，客服会编造不存在的退货政策，带来合规风险 ● 更细的策略可以让客户端根据业务场景动态传不同的 Temperature，后端不做一刀切 ● 还可以进一步把 Temperature 与其他参数（Top-p、frequency_penalty）组合使用，比如客服可以叠加 Top-p=0.1 进一步锁定；头脑风暴可以叠加frequency_penalty 增加多样性 ● 核心思想：Temperature 不是"模型风格"而是"产品设计的按钮"——它应该跟着业务语义走，而非被设成一个全局常量
